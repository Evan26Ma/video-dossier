# 踩坑清单

按「会在哪一步炸」分组。每条都是实战撞过的，不是推测。

## 一、子代理（最容易整批白干的一步）

1. **不要让代理把大 JSON 当返回值回传**。返回值通道会在几十 KB 处**静默截断**（不是报错，是看起来成功但内容少了一截）。真实事故：22 片大纲里第 8 片之后全部丢失，89,901 字符打水漂，只能整批重跑。**正确做法**：任务书要求代理 `write` 到指定文件，只回一行 `DONE <file> n=<条数>`。
2. **返回 null 不等于没干活**。有过代理返回 null 但结果文件已经落盘的情况。重派之前先 `ls` 一下目标文件。
3. **并发不要超 4**。实测 16 并发大面积返回 null；4 个一组稳定。任务重（读长文 + 写大 JSON）时更要压到 2–4。
4. **代理不守 schema 是常态**。同一批任务里出现过：时间键名 `startSeconds` / `startSec` / `timestamp` / `time` 四种；主题缺 `endSeconds`；描述藏在 `note` 或 `text` 里；`kind` 出现在主题级或条目级。**合并脚本必须多键名容错**，并把「需要规范化的条目数」写进产物（`mergeRule.schemaTolerance`）——这个数字异常高，说明任务书写得不清楚。
5. **任务书里要把「错字」说清楚**。ASR 会把专有名词写错（政治课：马原→马源/马云、唯心唯物→维新维物、旱区→汉区、大题→大体、枫桥经验→风桥经验）。不提醒，代理就会照着错字编。

## 二、采集

6. **评论接口对匿名极不友好**：`x/v2/reply` 的 `ps` 上限是 20（写 49 直接 `-400 ps out of bounds`）；`x/v2/reply/wbi/main` 对未登录返回 `-403`；官方 `x/v2/reply/main` 即使带 wbi 签名也会返回 `cursor.is_end=true` 且只给少量楼层。**结论**：要么明确声明「只采到可见楼层」，要么就别采评论。
7. **弹幕可能是 0，而且是真的 0**。要三方交叉验证：`view.stat.danmaku`、`x/v1/dm/list.so`（空壳 XML）、用户端下载的弹幕文件（ASS 的 `Dialogue:` 行数）。标题写「含弹幕」的录屏，弹幕是**烧录在画面像素里**的，不是接口数据。
8. **画质阶梯**：匿名最高到 1080P（`30080`），**1080P60 需要大会员**；`fnval=1` 的 durl 只给到 720P 单文件；要音频就选 `30232/30216/30280` 这些 m4a 音轨。别默认拉最高画质——先看 `-F` 的 filesize。
9. **`copyright=3` 之类的字段语义未定义**：原样记录 + 在口径里写「语义未定义，不做解读」，不要硬猜。
10. **采集必须是一次序列**：视频很新时播放量分钟级变化，分几次抓会让「互动率」这类同分母比率失真。所有字段共用同一次采集的 `collectedAt`。

## 三、转写

11. **VAD 会吃掉段内小停顿**。开 `vad_filter=True` 后 segment 之间的间隔才是可测的，段内停顿被合并——所以「停顿次数」是**系统性低估**，只能当「明显静默」看。这条必须写进口径。
12. **Whisper 会复读**。出现过「比」连续 149 次、「额」长串。做一次折叠对照（同一 1–12 字短串连续重复 ≥4 次即折叠），把影响幅度算出来（实测 0.6%），主口径仍用 raw，但要在报告里标注伪影词。
13. **转写可能几乎没有中文标点**。实测一份 2.7 小时转写里逗号 291 个、句号 0 个——断句正则必须包含 `,` 和 `，`，否则整篇被当成一句话，「提问句统计」直接归零。
14. **单进程跑 ASR**。多个 faster-whisper 进程同跑会把 6GB 显存打满且零产出。GPU 不可用时回退 `cpu/int8` 并在报告里记录实际设备与耗时。
15. **时长要对账**。ASR 时长与视频分P 时长偏差必须 <1%，否则先怀疑截断，别急着进统计。

## 四、画面

16. **逐帧内容哈希会被「滚动的东西」骗**。屏幕上有聊天窗/弹幕/视频窗时，整帧 dHash 几乎每帧都不同（实测 4892 帧只去掉到 524 页，保留率 10.7%），必须再做一次**按时间分层抽样**（例如每 30 秒取该时段最早一张），否则 OCR 成本失控。
17. **屏幕状态键不要用整页文本**。聊天滚动会让每个页面都变成「新状态」（实测算出 141 个假状态）；改用「该页抽到的数字集合」当状态键，收敛到 55 个。另外「无文字」的页面必须归成一个 `EMPTY` 状态，而不是每页一个。
18. **阶段产物不一致**：OCR 阶段落的 `_ocr-raw.json` 里**没有**分类后的 `dashboardText`（那是 report 阶段才算出来写进 `slides.jsonl` 的）。下游要屏幕证据就读 `slides.jsonl`，别读中间文件。
19. **抽帧中间产物很占地方**：4892 张 1080P JPEG 约 1GB，落盘后立刻删；`-q:v 3` 足够 OCR 用。pass1 的抽样帧也是临时的。
20. **文本块分类只能是启发式**。关键词匹配会把纯聊天正文归到 `other`（聊天规则通常只匹配 `[N条]`/`有人@我`/`@某人`），所以要在口径里写「分类是启发式、非人工标注」，并且**OCR 文本不参与统计**。
21. **OCR 会读错数字**（屏幕 `1,234` → OCR `1.234`）。凡是引用屏幕数字，都要标注「未人工逐项校对」。

## 五、纠错（唯一容易「越改越错」的一步）

22. **对错字线索做字符串替换前，先判断「错串本身是不是真词」**。用 jieba 的 `dict.txt`（约 35 万词）筛：不是真词 → 默认采纳；是真词 → 默认拒绝。真实反例：`意志→意识` 会把「不以人的意志为转移」改错；`整体→真题` 会误伤「整体思想」；`考验→考研` 会误伤「核心考验」。
23. **代理给的目标串也可能是错的**。真实反例：代理说 `4D → AD`，但上下文（「4D 说确定不移的因素」）明确是选项 D，正确改判是 `4D → D`。所以**人工裁决闸门**是必须的：每条采纳都要有依据，每条拒绝都要有理由。
24. **替换必须是纯字符串操作，并做长度守恒校验**：`Σ(新串长−旧串长)×命中次数` 必须等于 clean 稿与 raw 的长度差。不相等就说明发生了预期外的改写。这条断言能把「偷偷重写」抓住。
25. **真词用短语级替换**。要改「大体→大题」但怕误伤「大体上」，就用 `notFollowedBy` 护栏；要改「整体→真题」但怕误伤「整体难度」，就换成 `整体入手→真题入手` 这类更长上下文的规则。

## 六、工程与协作

26. **「仓库零改动」的判据不能是「状态逐行相同」**。有并行工作流时它会自己提交文件（真实事故：工作期间 HEAD 从 `bc351e9` 前进到 `052cde0`，状态行数从 69 变 55）。改用**子集判据**：当前脏文件集合 ⊆ 开工基线集合，且产物路径不出现在仓库状态里。开工前先存一份 `git status --short --branch` 基线。
27. **Windows 下 Python 中文输出**：设 `PYTHONIOENCODING=utf-8`（以及 `PYTHONUTF8=1`），否则控制台是 GBK，轻则乱码重则 `UnicodeEncodeError`。
28. **临时目录与缓存也指到工作盘**：`TEMP` / `TMP` / `MPLCONFIGDIR` / `PIP_CACHE_DIR`，并用 `pip install --target <workdir>/tools/pylibs --no-cache-dir` 装依赖，避免污染系统盘。
29. **路径含中文/空格一定要引号**；PowerShell 里用单引号包路径最省心。
30. **README/口径先写，报告后写**。口径是给未来的自己看的：没有它，三个月后这堆 JSON 就是不可用的数字。

## 七、出 PDF（无头 Chromium）

31. **不要给无头 Chromium 传全新的 `--user-data-dir`**。本机实测：带一个全新 profile 路径时 `--print-to-pdf` 会**挂住不返回**（45 秒超时都不出片，profile 目录里在下载组件、留下 `Cr24` 的 .tmp）；不传它则 5 秒出片。用默认 profile 就行。
32. **Chromium 的临时 profile 建在 `TMP` 里**（名字形如 `HeadlessChrome for Testing<pid>`）。如果调用方的 `TMP` 指向了产物目录（`set TMP=.` 很常见），产物根里就会多出一坨浏览器垃圾。**给子进程显式指定 `TMP`/`TEMP` 到 `tmp/`**，并把 `cwd` 也指过去。顺带在 `.gitignore` 里加 `HeadlessChrome*/`。
33. **PDF 里的背景色要不要印出来，取决于 `print-color-adjust`**。少了它，深色结论块、占比条、色块会全变成白底黑线——杂志风就废了。写 CSS 时在 `@media print` 里加 `print-color-adjust:exact`，出片后用 PyMuPDF（`fitz`）把页面渲成 PNG **亲眼看一眼**，别只看「PDF 生成了」。
34. **别只看文件大小和页数就宣布成功**。`*.pdf` 里全是压缩流，拿 `grep ' rg'` 判断有没有颜色是假的；要么渲图看，要么别下结论。
35. **每章强制分页（`page-break-before:always`）在短内容上会产出一堆半页空白**。按篇幅自适应：主题/知识点/图表的量够大才分页（本项目的阈值：`主题数 + 知识点数/4 + 2×图数 ≥ 25`），否则连着排。
