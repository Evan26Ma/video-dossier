# 报告模板

主报告是给人看的入口，口径是给未来的自己看的底座。**两者都要：** 报告里每个数字都要能指回产物文件与字段。

> **先看默认样式**：这套流水线默认出的是**杂志版**（`magazine.html` → `magazine.pdf`，见 `references/杂志文案.md`）。
> 本文档描述的是那份 **Markdown 数据报告**——它是口径与数据的完整底稿，也是杂志版排版失败时的回退输入。
> 两份的分工：杂志版负责「让人愿意读完」，Markdown 版负责「每个数字都能查到出处」。

文件名建议：`报告-<视频标题>-数据与内容.md`（放在 run 根目录，PDF 步骤会自动找它）。

---

```markdown
# <视频标题>（<BV号 / 文件名>）· 数据与内容报告

- 生成时间：<YYYY-MM-DD>
- 数据采集时刻：**<collectedAt，带时区>**（所有平台计数都是这一瞬间的累计值快照）
- 来源：<BV 号 / 本地文件路径> · UP/作者：<name> · 时长：<hh:mm:ss>（<N> 个分P/音轨）
- 工作目录：`<runRoot>`

> 一句话结论：<这场/这段视频是什么、谁讲给谁听、核心结构是什么、最显眼的数字是什么。>
> 一句话要给读者「值不值得细看」的判断依据。

---

## 1. 平台数据（截至采集瞬间）           ← local 模式删掉本节

| 指标 | 值 | 口径 |
|---|---|---|
| 播放 / 点赞 / 投币 / 收藏 / 分享 / 评论 / 弹幕 | … | 累计值 |
| 同时在看 | … | 瞬时值 |
| 发布时刻 / 距采集 | … | |

**派生比率**（同一次快照）：互动率、藏播比、赞播比、评播比、投币/点赞、分享/点赞。

> 提示一句「视频过新，比率不可横向比较」之类的时效警告。

## 2. 内容：这段视频讲了什么

### 2.1 结构（一级主题 N 个 / 二级知识点 M 条）

按 `kind` 汇总时长与占比的表格 + 时间轴骨架表（起止 / 时长 / 类型 / 主题）。

### 2.2 核心信息（原文可复核）

把讲者给出的**具体结论、数字、方法**逐条列出，每条后面用括号带上可复核的原文片段或大纲条目 id。这一节是整份报告最有价值的部分——读者要的是内容，不是统计。

### 2.3 大纲样例

从 `content/outline.md` 里摘 1–2 个主题，连时间戳、口播原文、屏幕证据一起贴，让读者知道粒度。

## 3. 语言与节奏

转写段数 / 总字数 / 汉字数 / 语速 / 人声占比 / 开头结尾静音 / 停顿分档 / 最长停顿 / 提问句；
高频词表与口头禅表（**标注复读伪影**）；
领域术语命中表（**标注词表里混入的日常词会造成高估**）。

## 4. 图表

把 `stats/figures/*.png` 用相对路径内嵌（`![说明](stats/figures/xx.png)`），并在图下写 2–4 条**图里能直接读出的结论**（例：第 20 分钟语速峰值 310 字/分，对应讲数据那一段）。

## 5. 屏幕内容（若有画面层）

画面实况一句话（是课件？桌面共享？纯口播？）+ 质量读数（页数 / 置信度 / 看板占比 / 状态数）+ 挖到的关键屏幕文本（题目原文、看板数字…）。**不要**把 OCR 全文贴进来，贴要点并指向 `slides/`。

## 6. 数据质量、误差与「为什么这么定口径」

逐条写：空缺与零的区分、复读伪影的敏感性对照、纠错的采纳/拒绝与长度守恒、OCR 已知错字、以及**没做/拿不到**的东西。

## 7. 后续可以做的调查清单

列 5–10 个具体题目，每条注明「用哪个文件的哪个字段」。这是让档案产生复利的一节。

## 8. 文件索引

用表格列出 run 根下的每个产物与它的用途；标注哪些是原始数据、哪些是中间产物、哪些是可删的大文件（音轨/视频）。
```

---

## 写完报告后的自检

1. **每个数字都有出处**：随便挑 5 个读数，能不能在两分钟内指到文件与字段？指不到就补引用或删掉。
2. **没有「大概/左右/估计」**：拿不到的就写「不可得」，别用模糊词糊过去。
3. **降级都写出来了**：OCR 命中率低、ASR 回退 CPU、代理重派过——都在「数据质量」一节里。
4. **时效警告到位**：平台比率、瞬时在线数这类会变的量，都标了采集时刻。
5. **可搬走**：文档里的路径都是相对 run 根的，整个目录拷到别处依然能读。
