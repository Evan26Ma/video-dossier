# 案例：一场 2 小时 43 分的直播录播

> 本文只保留**方法论与聚合读数**，已去掉视频标识、讲者信息、逐字稿原文、屏幕上的具体数字与聊天名称。

## 输入

- B 站录播，2 个分P（一个含弹幕烧录、一个纯净版），纯净版 9738 / 9785 秒
- 只有匿名可得的公开接口权限（无登录态），匿名最高画质 1080P
- **发布的第 45 分钟**开始采集数据

## 关键发现（这些是转写单独给不出的东西）

| 发现 | 怎么发现的 |
|---|---|
| 页面弹幕 **0 条**，标题里的「含弹幕」是**烧录进画面像素**的 | 三方交叉验证：`stat.danmaku`=0 + 弹幕列表接口返回空壳 + 客户端下载的弹幕文件 `Dialogue:` 行数为 0 |
| 官方**没有章节标记**（`view_points`=0），也没有字幕轨 | `player/v2` 返回空 |
| 评论区**匿名拿不全**：接口自报 40+ 条，实际只能取到十几个楼层 | `reply/wbi/main` 未登录 −403；`reply/main` 返回 `is_end=true` 且只给少量楼层 |
| 屏幕上**不是课件**，是直播间桌面共享（数据看板 + 聊天窗 + 播放窗） | pass1 抽样 OCR 后发现平均每帧 343 字、含文本帧占比 100%，打开页面图确认 |
| 开头 **137 秒是纯静音**（平均 −40.8dB），不是 ASR 丢字 | ffmpeg `volumedetect` 对 0–137s 与正文分别测音量 |
| ASR 出现**复读伪影**（某个字连续 149 次） | 折叠对照：影响 0.6%，主口径仍用 raw 并在报告标注 |

## 流水线读数

| 阶段 | 读数 | 耗时 |
|---|---|---|
| 平台采集 | 一次序列采完，字段含播放/点赞/投币/收藏/分享/评论/弹幕/在线/标签/分P 分辨率 | 约 10 秒 |
| 转写 | 274 段 / 39,847 汉字 / 244 字每分钟 / 人声占比 95.3% | **114 秒**（GPU float16，2.7 小时音频） |
| 切片 | 600s 窗口 + 150s 重叠 → 22 片 | 秒级 |
| 大纲 | 22 个子代理并行（每批 4 个）→ 合并后 **56 个一级主题 / 287 条知识点**，铺满覆盖率 98.6%、≥420s 空档 0 处 | 约 15 分钟 |
| 纠错 | 381 条线索 → 257 条候选 → **采纳 238 条 + 5 条短语规则（命中 484 次）、拒绝 19 条（65 次未改）**，长度守恒 −33 = −33 | 秒级 |
| 统计 | 逐分钟序列 + 词频 + 口头禅 + 六类术语命中 + 4 张图 | 约 20 秒 |
| 画面层 | 4892 帧 → dHash 去重 524 页 → 分层抽样 170 页 OCR → **55 个屏幕状态**，平均置信度 0.954 | **约 25 分钟**（其中 OCR 715 秒） |
| 校验 | 49 项断言 | 秒级 |
| 报告 + PDF | 主报告 + 口径 README → PDF | 分钟级 |

## 这次踩的坑（都已沉淀成 references）

1. **让子代理把大 JSON 当返回值回传 → 静默截断**。丢了 89,901 字符，整批重跑。改成「写文件 + 只回一行」。
2. **子代理不守 schema**：时间键名出现 `startSeconds`/`startSec`/`timestamp` 三种，主题普遍缺 `endSeconds`，描述藏在 `note`/`text`。第一版合并脚本只认一种键名 → 7 个切片解析出 0 条知识点、留下 4 处假空档。
3. **逐帧 dHash 被滚动内容骗**：4892 帧只去掉到 524 页（保留率 10.7%），必须再做按时间分层抽样，否则 OCR 成本失控。
4. **屏幕状态键用整页文本会爆炸**：一度算出 141 个假状态（聊天每滚一行就一个新状态）；改用「该页抽到的数字集合」当键，收敛到 55 个。
5. **纠错表里有会改错原文的条目**：`意志→意识` 会把「不以人的意志为转移」改错、`整体→真题` 会误伤「整体思想」。加了一道「错串是不是词典真词」的自动筛查 + 人工裁决闸门。
6. **代理给的目标串也可能是错的**：它说 `4D → AD`，但上下文明确是选项 D。所以每条采纳都要人工过一遍。
7. **并行工作流会改仓库**：工作期间 HEAD 被别的流程推进了一次提交，导致「状态逐行相同」的零改动校验失败。改成子集判据才稳。

## 这条流水线适合什么、不适合什么

**适合**：有明确结构的长视频（课程、直播、讲座、访谈、会议）——转写 + 大纲 + 屏幕证据能给出比「AI 总结」靠谱得多的东西；需要把结论落成可复核数据的场景。

**不适合**：
- 纯音乐/无语音视频（转写没内容，只剩画面层）
- 强依赖视觉效果的内容（低成本 ASR 与移动版 OCR 都读不懂画面里的细节）
- 要求「一句话总结」的场景（这套东西产出的是档案，不是摘要）
- 需要精确逐字稿的场景（ASR 专有名词一定有错字，只能做术语级修正）
