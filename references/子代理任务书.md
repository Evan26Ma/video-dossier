# 子代理任务书（outline 阶段）

`outline` 阶段是唯一必须由**主 agent 亲自派发**的一步。脚本只负责把转写切成窗口切片，读转写、判定主题与知识点的活由子代理做。

## 一、先看切片

`build_slices.py` 会产出：

```
content/_slices/
├─ index.json          {duration, windowSeconds, overlapSeconds, slices:[{id,file,startSeconds,endSeconds,lineCount,charCount}]}
├─ slice-01.md         # 切片 01 · 窗口 00:00:00–00:10:00（绝对秒 0–600）
└─ ...
```

每个切片文件里每行形如：

```
[00:02:17] (137.0s) 喂能听见吗喂不是哦现在有了刚才一声没声音吗
```

括号里的秒数就是**绝对秒**——它是唯一可信的时间来源。

## 二、切片参数怎么定

- 窗口默认 600s、重叠 150s。切片太短会让代理看不到上下文（主题被切断），太长会让它在一次回答里塞太多内容而漏标。
- 一个切片建议控制在 **2000–4000 字**转写。2–3 小时的课通常切出 15–25 片。
- 重叠是**去重的前提**：合并时只保留落在该片「核心区」的条目（第一片 `[0,end]`，其余 `[start+overlap,end]`），全片任一时刻因此恰好归属一个核心区，重叠区的重复条目天然被丢掉。

## 三、任务书模板

把 `<>` 里的内容按本次 run 替换。**一次只派一个切片。**

```
你在给一段视频（<视频标题>，<学科/领域>）的转写做逐段内容标注，产出可复核的两级大纲。

## 步骤
1. 用 read 工具读取切片：<slice.file>（窗口 <slice.id>，绝对时间 <start>–<end> 秒）。
   文件内每行格式 `[hh:mm:ss] (1234.5s) 文本`，括号里的秒数就是该句开始说话的时刻。
2. 产出结构化结果后，**必须用 write 工具**把 JSON 写到：<content/_outline/slice-XX.json>
   文件内容就是 schema 要求的 JSON 对象本身，不要包 markdown 代码块、不要加解释文字。

## 硬约束
- 转写来自语音识别，**专有名词常有错字**<若已知典型错字，在此列举，例如：马原→马源/马云、
  唯心唯物→维新维物、旱区→汉区、大题→大体、枫桥经验→风桥经验>。按语境理解，但**不要**在输出里
  改写转写原文之外的内容。
- 时间戳取「该主题/该知识点**第一句**话所在行的括号秒数」。宁可晚一秒，不要早一秒。
- 所有时间戳必须落在 <start> 到 <end> 秒之间，且同级内严格升序。
- 只写切片里真实出现过的内容，**禁止编造**。若是闲聊/答疑/互动/念广告/调试设备，kind 记为
  答疑/互动/其他，points 写它实际在聊什么。

## 结构
- `windowSummary`：2–3 句，这一窗口在干什么。
- `themes`：一级主题，通常 1–3 个，按自然段落切分。
- theme 内 `points`：二级知识点条目，每条是一个可独立命名的知识、结论、方法、例题或明确交代的事项；
  `excerpt` 给该条目起点的**原文首句（≤60 字，照抄转写）**作为可复核证据。
- `tags` 只能取：["<profile.outlineTags 里的值>"]。
- `kind` 只能取：["<profile.outlineKinds 里的值>"]。

最后只回一行：`DONE <content/_outline/slice-XX.json> points=<条目数>`。
```

## 四、派发规则

1. **并发 ≤4**，一批一批来。重任务（长切片 + 大 JSON）压到 2–4。
2. **结果必须写文件，返回值只回一行**。这是最重要的一条（见 `踩坑清单.md` 第 1 条）。
3. **返回 null 先查文件**：`ls content/_outline/`，文件在就别重派。
4. **重派只重派失败的片**，不要整批重跑。
5. 若允许指定模型：任务重的用更稳的模型，只传 `model`、不要同时传 `provider`（有的 harness 传了 provider 会一律返回 null）。

## 五、合并与自查

```bash
python <skill>/scripts/merge_outline.py --config config.json
```

看四个数：

| 字段 | 期望 | 异常说明 |
|---|---|---|
| `problems` | `[]` | 任何条目都意味着某片文件缺失/解析失败/核心区零产出 |
| `mergeRule.schemaTolerance.pointsNormalized` | 可以高（说明代理用了别的键名，容错生效） | 但如果等于总数，说明任务书里的字段名没讲清楚 |
| `stats.tiledCoverageRatio` / `annotatedSpanRatio` | 都 ≥0.9 | 低说明大量内容没被标到 |
| `stats.gapAlertCount` | 0 | 有就逐个读窗口核查，判断是「代理漏标」还是「这段本来没内容」 |

**空档核查不能只看时间**：一段 5 分钟的空档可能是老师在放视频、也可能是代理漏了一整块。读转写对应窗口再判断，并把结论落成文件（只在对话里说「查过了」等于没查）。
