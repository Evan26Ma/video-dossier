# 画面层（抽帧 → 去重 → OCR → 屏幕状态）

这一步回答一个转写答不了的问题：**说话的时候屏幕上有什么**。课件、讲义、问卷看板、试卷原文、聊天、错误提示，都在这里。

## 一、四步走，别跳步

| 步 | 做什么 | 为什么不能省 |
|---|---|---|
| **pass1 画像** | 每 10 秒抽 1 帧（约几百帧），只 OCR 其中 30 帧做抽样 | 先判断「画面里到底有没有字」，避免为了几行字跑几千次 OCR |
| **pass2 取页** | 每 2 秒抽帧 + dHash 去重，得到「页面」 | 视频里同一屏会持续几分钟，不去重就是几十倍浪费 |
| **分层抽样** | 从去重页里每 `ocrBucketSeconds`（默认 30s）取该时段最早一张 | **逐帧 dHash 会被滚动内容骗**（聊天窗/弹幕/视频窗一直在动），必须再按时间抽样 |
| **report 聚合** | 文本块分类 + 按「数字集合」聚合成屏幕状态 | 直接按整页文本聚合会得到上百个假状态 |

## 二、参数与阈值

| 参数 | 默认 | 说明 |
|---|---|---|
| `pass1EverySeconds` | 10 | 画像抽样间隔 |
| `pass1ProbeFrames` | 30 | pass1 实际 OCR 的帧数（均匀取样） |
| `pass2EverySeconds` | 2 | 取页抽样间隔；素材长就调大 |
| `hammingMax` | 6 | dHash（8×8 灰度均值哈希，64 bit）与**上一张保留页**的汉明距离阈值 |
| `ocrBucketSeconds` | 30 | OCR 分层抽样桶宽 |
| `ocrMinScore` | 0.6 | 「有文字页」的平均置信度下限 |
| 判定 | — | 含文本帧占比 ≥0.30 → `usable`；<0.05 → `unusable`（停止 OCR 并如实报告）；中间 → `degraded` |

抽帧命令要点：`ffmpeg -vf fps=1/<every> -q:v 3`（JPEG 质量 3 够 OCR 用），中间帧**落盘后立刻删**（4892 张 1080P 约 1GB）。

## 三、状态聚合：用数字，不用文本

屏幕状态键的优先级：

1. 该页抽到的**数字集合**（百分比 + `a/b` 分数对）——最鲁棒，聊天滚动不影响它；
2. 没有数字时退化为「该页看板文本归一化后前 80 字」；
3. 连看板文本都没有 → 全部归成一个 **`EMPTY`** 状态（**不要**每页一个，否则状态数会爆炸：实测 170 页一度算出 141 个假状态）。

## 四、文本块分类是启发式

每页的文本块分五类：`dashboard` / `chat` / `chrome` / `noise` / `other`，规则来自 profile 的 `screen`：

- `dashboardWords`：领域关键词（例：问卷、有效、使用者、勾选、截至、平均分…）+ 纯百分比/分数对正则；
- `chatPatterns`：`[\d+条]`、`有人@我`、`@某人`；
- `chromeWords`：播放器/浏览器 UI 词（问AI、搜索、Microsoft…）；
- `topicLabelPattern`：形如「XXX一页纸」「XXX讲义」「XXX材料」的标题。

**必须写进口径**：这是启发式，不是人工标注。典型误差：纯聊天正文会落进 `other`（聊天规则只匹配带 `[N条]` 这类标记的），所以 `other` 数量大不代表没识别到东西。

## 五、产物

```
slides/
├─ pages/*.jpg              去重+抽样后的页面图（保留 JPEG 原帧，不做 PNG 无损重编码）
├─ slides.jsonl             每页一行：时间戳 / dhash / 文本块(含分类) / dashboardText / 数字集合
├─ ocr-quality.json         质量读数：页数 / 置信度 / 各类块数 / 状态数 / verdict
├─ 屏幕状态时间轴.json        按状态聚合：首现时间、命中页数、百分比与分数对、最全看板文本
├─ 屏幕内容时间轴.md         人读版
├─ 屏幕关键文本.json         关键词/正则抽出的条目（题目原文、看板数字、标题…）
└─ pass1-profile.json       pass1 判定依据
```

## 六、把画面挂回大纲

`merge_outline.py` 会给每条知识点挂 `slideExcerpt`：取时间落在 `[起点−30s, 起点+90s]` 内最接近的 OCR 页面的看板文本。

**注意**：要读 `slides.jsonl`（里面有分类后的 `dashboardText`），不要读 OCR 阶段的中间文件——中间文件里没有这个字段。

挂上比例（`pointsWithSlideRatio`）在 30% 以上算正常；太低说明屏幕内容与讲解不同步（常见于纯口播、或老师没共享屏幕），这时应放弃画面证据而不是硬凑。

## 七、能力边界（写进口径）

- OCR 会读错数字与标点（实测屏幕 `1,234` → OCR `1.234`，逗号常被读成句点）→ 引用屏幕数字必须标注「未逐项校对」。
- 帧时间戳按 `fps=1/N` 均匀采样推算，误差 ≤1 帧。
- 小字幕（弹幕、聊天）在低码率源上几乎不可读：**480P/105kbps 的源不要指望做画面文字挖掘**，要挖就先换成匿名可得的高码率流（1080P 常可以，1080P60 通常要大会员）。
- 画面里是谁的屏幕、是否共享了隐私内容（群名、未读消息、账号），**发布前务必回看抽出来的页面图**。
